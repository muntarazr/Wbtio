# المنتجات — Productized Services

> القاعدة: **تبنيه مرة، تبيعه عشر مرات.** كل شي بهذا المجلد لازم يكون قابل للتسليم لعميل جديد بتعديل نص، مو بإعادة بناء.

كل منتج بمجلده لازم يحتوي أربعة أشياء، وإلا مو منتج:

| العنصر | ليش |
|---|---|
| **workflow / كود شغّال** | بدونه هو عرض سعر مو منتج |
| **دليل تركيب بالإنكليزي** | يتسلّم للعميل كما هو — يوفر عليك ساعات دعم |
| **ديمو يشتغل بدقيقة** | العرض يبيع، الشرح ما يبيع |
| **صفحة بيع للعميل** | ترسلها قبل المكالمة، تقصّر المكالمة للنص |

## ترتيب البيع — مهم

**ابدأ بالمنتج ٢ لا بالمنتج ١.**

| | فرز البريد | التقرير الأسبوعي |
|---|---|---|
| مخاطرة العميل | يرد على زبائنه نيابة عنه — **مخيف** | إيميل يقرأه هو فقط — **بلا مخاطرة** |
| مدة الإقناع | وضع ظل ثلاثة أسابيع | مكالمة واحدة |
| الاعتراض المتوقع | «شلون أضمن ما يغلط مع زبوني؟» | تقريباً لا يوجد |

**التقرير الأسبوعي باب دخول.** العميل يشتريه بلا خوف، وبعد شهر من الثقة يشتري فرز
البريد وأنت داخل بالفعل.

## أفكار للمنتج القادم (بترتيب الأولوية)

1. **مساعد RAG على مستندات الشركة** — أعلى سعر بالسوق (800 – 2000$)، ويكمّل منتج ١
   طبيعياً: يصير مصدر الحقائق اللي يرد منها المساعد. المهمة `M23` باللوحة.
2. **أتمتة متابعة العملاء المحتملين** — تذكير تلقائي بالمتابعة. تبيعه لأي شركة عندها مبيعات.
3. **منتج رابع حسب طلب السوق الفعلي** — بعد سنة تعرف شنو يطلبه العملاء فعلاً،
   ابنِ ذاك لا ما تتخيله. المهمة `S20`.

**لا تبني الثالث قبل ما تبيع الأول أو الثاني مرتين.** بناء منتجات بلا عميل هو نفس فخ
«بناء SaaS خاص» المكتوب بالخطة.
